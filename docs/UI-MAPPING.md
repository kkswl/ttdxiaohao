# 方案 B 到原生组件

| 参考原型 | 当前原生实现 | 差异 |
| --- | --- | --- |
| 顶部规则与概览 | 分页规则按钮、状态 badge、读取时间、切换 / 刷新按钮 | 静态 inputs 不能被结果随意改成动态下拉 |
| 左侧账号池 | grid 第 1 列、账号 card、状态 badge | 每页 4 个账号 |
| 中间用户列表 | grid 中间 2 列、字符串 table、加入 / 移出按钮 | 表格不注入复选框；每页 8 位用户 |
| 右侧分配预览 | grid 第 4 列、预览 table、一次性确认按钮 | 确认依赖持久预览而非浏览器 JS |
| 账号编辑弹窗 | 清单「账号维护」字段 + 结果确认 card | 原生协议没有自定义 HTML 弹窗 |
| 扫码登录 | image +「检查并完成登录」；保留仅检查、预览完成以及同一小号的原生面板入口 | 参照用户中心已授权后完成的协议；每次点击只检查一次；真实完整登录仍待现场验收 |
| 目录浏览 | 目录表格、进入 / 选择 / 分页按钮和 text ID 输入 | 不将目录 ID 作为 number；已通过真实宿主读写验证 |
| 操作记录 | 脱敏 table | 与原网关播放日志分开 |
| 深色 B 版 | 只使用原生 tone / card / table / button | 自动采用宿主主题，不固定深色，无自定义 CSS |
| 手机布局 | 宿主 grid 自动单列 | 响应式行为以真实宿主为准，尚未验收 |

已使用 ui-ux-pro-max 做布局指导检索。设计系统和一次收窄重试均未取得适合本项目的产品匹配，因此不采用推荐配色与落地页结构。界面服从已选 B 版与宿主组件，采用技能通用指南检查明确的按钮文字、状态文本、先预览再提交和逐项失败反馈。

插件只描述组件，不控制字体、焦点样式和控件实际尺寸。浅色 / 深色对比度、键盘操作及移动端表现必须在宿主导入后验证。本地 JSON 结构校验不证明这些视觉与交互要求已经通过。

0.2.1 已导入实际宿主检查桌面浅色、深色三栏；工具按钮和用户选择按钮改用原生 grid，避免默认纵向堆叠挤占区域。两种主题截图均已保存，最后恢复浅色。移动端、键盘与完整错误状态检查仍未完成。
